# Лабораторна робота №3 — синтаксичний аналізатор підмножини C

Дисципліна: системне програмування.

Навчальний аналізатор на Python із PLY (аналогом Lex/YACC): лексичний аналіз, LALR(1)-розбір, побудова AST, перевірка імен, виконання AST, генерація Python-коду та інтерактивна графіка JavaScript/SVG.

## Запуск

Потрібен Python 3. PLY 3.11 включено у `vendor`, тому встановлювати залежності для звичайного запуску не потрібно.

```bash
cd lab_3
python3 compiler.py examples/gcd.c --report
python3 build/generated.py
python3 tests.py
xdg-open build/ast.html
```

Основний приклад — алгоритм Евкліда для НСД(35, 64). Аналізатор і згенерований Python повертають **1**. Тести перевіряють обчислення, помилки, області видимості, пріоритети, скорочене обчислення логічних виразів і НСД для різних пар чисел.

Запуск проєкту перевірено в Ubuntu у VirtualBox. Файли перенесено з Windows через спільну папку. Docker-конфігурацію додано, але контейнерний запуск не перевірено.

## Як працює

`C-код → лексер → токени → LALR-парсер → AST → перевірка імен → інтерпретація / генерація Python / SVG-візуалізація`.

Вхідна мова — підмножина C. Інструмент реалізований на Python. Цільова мова згенерованого коду — Python. C-програма не компілюється через GCC: її читає власний аналізатор.

У графічному AST вузли й зв'язки малюються JavaScript у SVG. Є масштабування, переміщення та згортання гілок. Сторінка працює без інтернету; дерево показує структуру програми, а не трасу виконання циклу.

## Файли

| Файл | Призначення |
|---|---|
| compiler.py | Лексер, граматика, AST, семантика, інтерпретатор і генератор |
| ast-viewer.html | Шаблон JavaScript/SVG-візуалізації; потрібний поруч із compiler.py |
| examples/gcd.c | Основний приклад НСД |
| examples/arithmetic.c | Перевірка пріоритетів |
| examples/error.c | Приклад синтаксичної помилки |
| examples/factorial.c | Додатковий приклад циклу |
| tests.py | Автоматичні перевірки |
| vendor/ | Стороння бібліотека PLY та її метадані |
| requirements.txt | Версія залежності |
| DEFENSE.md | Пояснення коду й теорії |

Після успішного запуску створюються `build/ast.json`, `build/ast.html`, `build/generated.py`. Параметр `--report` створює `parser.out` із таблицями/станами LALR. Ці результати та кеші не зберігаються в Git.

## Підтримка й обмеження

Підтримуються `int main()` / `int main(void)`, цілочисельні змінні, блоки, присвоєння, `if/else`, `while`, `return`, арифметика, порівняння, `&&`, `||`, `!`, унарний мінус та коментарі. Немає інших функцій, scanf/printf, for, масивів, вказівників, рядків, ++ або повної граматики C.

Цілі числа довільної точності; переповнення C int не моделюється. Ділення відкидає дробову частину до нуля. Неініціалізовані змінні отримують 0 за навчальною домовленістю. Ініціалізатор обчислюється до введення нового імені, тому затінення в ініціалізаторі відрізняється від C. НСД(0,0) прийнято рівним 0.

Інтерпретатор має ліміт кроків, згенерований Python — ні. Після помилки попередні результати в build можуть залишитися; перевіряйте повідомлення поточного запуску.

## Джерела та залежності

- [PLY](https://ply.readthedocs.io/en/latest/ply.html) — сторонній генератор лексерів і LALR-парсерів; його авторство та умови розповсюдження збережені у файлах бібліотеки.
- [Алгоритм Bison/YACC](https://www.gnu.org/software/bison/manual/html_node/Algorithm.html).
