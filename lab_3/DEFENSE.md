# Підготовка до захисту

## Як пояснити роботу за одну хвилину

«Я розробила аналізатор підмножини C на PLY — аналогу Lex/YACC. Лексер перетворює текст на токени. LALR(1)-парсер застосовує правила граматики та будує AST. Далі перевіряються оголошення й області видимості змінних. Інтерпретатор обходить AST та обчислює програму. Інший обхід генерує Python-код. Також дерево зберігається у JSON і в інтерактивному HTML. Повна граматика C та машинний код не реалізовані».

## Етапи на прикладі

Вхід: `int main(){ return 2+3*4; }`.

1. Лексер видає `INT MAIN ( ) { RETURN NUMBER + NUMBER * NUMBER ; }`.
2. Парсер перевіряє правила програми, блоку, return та виразів.
3. У AST буде `return → binary(+)`, із дітьми `number(2)` та `binary(*) → 3,4`.
4. Інтерпретатор спочатку отримує 12 для множення, потім 14 для додавання.
5. Генератор записує еквівалентний Python із виразом `(2 + (3 * 4))`.

## Питання по коду

**Де лексер?** `t_NUMBER`, `t_ID`, `t_comment`, `t_newline`, `t_error` та правила `t_EQ` тощо. `lex.lex()` збирає їх. Регулярний вираз у рядку документації функції описує токен. Ключові слова перевіряються у `reserved`, щоб `integer` лишалося ID, а `int` було INT.

**Де граматика?** Функції `p_program`, `p_block`, `p_binary` тощо. Рядок документації містить продукції. `yacc.yacc(method='LALR')` будує таблиці. `p[0]` — результат лівої частини; `p[1]`, `p[2]` тощо — значення символів правої частини. Це аналог `$$`, `$1`, `$2` у YACC.

**Чому `p[4]` в оголошенні?** У `INT ID '=' expression ';'` четвертий символ — expression. Його AST стає дитиною declare, а ім'я з `p[2]` — значенням вузла.

**Що таке AST?** Абстрактне синтаксичне дерево. Тут вузол — словник із kind, value та children. Дужки й крапки з комою потрібні для розбору, але не стають окремими вузлами. AST зберігає зміст конструкцій, а не всі деталі запису.

**Де семантика?** `check` перевіряє імена статично, навіть у невиконуваних гілках. `run` виконує дерево. Стек словників у run реалізує області видимості: пошук починається із внутрішнього блоку. Окремий виняток Returned переносить значення return через вкладені цикли й блоки.

**Де генерація коду?** `generate` обходить AST та створює вихідний текст Python. Унікальні імена на кшталт `v_1_x` зберігають затінення змінних, бо Python не створює область видимості для кожних фігурних дужок C. Це трансляція у високорівневу цільову мову, не генерація машинного коду.

**Навіщо cdiv?** Python `//` округлює до мінус нескінченності, а ціле ділення C — до нуля. `-7/3` має дати -2; остача -1. Використано точні цілочисельні дії без переходу до float.

**Як знаходяться помилки?** Невідомий символ — `t_error`; недопустима послідовність токенів — `p_error`; невідоме ім'я або дублікат — `check`; нуль у знаменнику або надто довге виконання — `run`.

## Теорія

**Що означає LR?** Читання зліва направо (Left-to-right) та відновлення правостороннього виведення у зворотному порядку (Rightmost derivation in reverse). Це висхідний аналіз.

**Що таке LALR(1)?** Look-Ahead LR з одним токеном випередження. Класичне пояснення побудови: створити LR(1)-стани й об'єднати ті, що мають однакові LR(0)-ядра, об'єднавши lookahead-множини. Таблиці компактніші, але деякі LR(1)-граматики після злиття мають конфлікти. Реальні генератори можуть обчислювати таблиці без явного створення всього канонічного LR(1)-автомата.

**Як працює YACC?** З граматики генерує таблиці ACTION/GOTO і код аналізатора. У runtime аналізатор тримає стек станів і значень, дивиться на поточний стан та lookahead. ACTION задає shift, reduce, accept або error. Shift споживає токен і кладе стан на стек. Reduce згортає праву частину продукції до нетермінала, виконує семантичну дію та переходить за GOTO. Accept означає завершення розбору.

**Shift/reduce?** В одному стані для того самого lookahead можливі зсув та згортка. Наприклад, після `2+3` перед `*` треба вирішити: згорнути додавання чи продовжити множення. Пріоритет `*` вище за `+`, тому обирається shift. У коді precedence перераховує рівні від нижчого до вищого.

**Асоціативність?** Для `10-3-2` ліва асоціативність дає `(10-3)-2=5`. За однакового пріоритету left веде до reduce, right — до shift, nonassoc — до помилки для відповідного ланцюжка. `%prec UMINUS` задає окремий високий пріоритет унарного мінуса.

**Dangling else?** `if(a) if(b) s1; else s2;`: else належить найближчому if. Правило if без else має нижчий пріоритет IFX, ніж ELSE, тому аналізатор зсуває else й приєднує його до внутрішнього if. IFX — лише маркер пріоритету, не вхідний токен.

**Reduce/reduce?** Для того самого lookahead можна згорнути дві різні продукції. Зазвичай треба переписати граматику, прибрати дубльовані або перекривні порожні правила. PLY/YACC можуть вибрати правило, записане раніше, але покладатися на порядок небезпечно. Пріоритети операторів переважно вирішують shift/reduce, а не замінюють виправлення reduce/reduce.

**Що буде без пріоритетів?** PLY за замовчуванням обирає shift у невирішеному shift/reduce; це не гарантія потрібного змісту. Конфлікти слід діагностувати й виправляти. У parser.out з --report можна подивитися продукції, стани, переходи й альтернативні дії. Рядки з `!` можуть означати альтернативи, вже відкинуті пріоритетом: вони самі по собі не доводять наявності невирішеного конфлікту.

**Синтаксис проти семантики?** `return x;` може відповідати граматиці, але бути семантично хибним, якщо x не оголошено. `return +;` хибне вже синтаксично. `return 1/0;` синтаксично правильне, але у нашому інтерпретаторі спричиняє помилку виконання.

## План демонстрації

1. Покажи README, підтримуваний синтаксис і чесно назви обмеження.
2. Запусти gcd.c: очікується 1 для 35 та 64; поясни алгоритм Евкліда.
3. Відкрий AST і знайди while, остачу % та return.
4. Покажи generated.py, запусти його: теж 1.
5. Запусти arithmetic.c: результат 14 демонструє пріоритет.
6. Запусти error.c: покажи діагностику пропущеної крапки з комою.
7. Запусти tests.py; відкрий правила p_binary та precedence, поясни один reduce.

Не називай проєкт повним компілятором стандарту C. Перед захистом самостійно зміни число 5 на 6 у factorial.c і передбач результат 720; додай вкладений блок та поясни область видимості. Це допоможе відповідати по коду, а не завчати формулювання.
